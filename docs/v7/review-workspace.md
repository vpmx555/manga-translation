# Storylens review workspace

Graph, analyze and reanalyze use the same offline, end-user review interface. The canonical template is `src/manga_pipeline/review/story_graph.html`; the automatic stage renderer and standalone viewer both use it.

## Review workflow

- The chapter map connects chapter → scenes → events. The collapsible sidebar continues to individual utterances and supports arrow-key navigation.
- Select an event to open its source text, speaker/listener decisions, independent model-confidence scores, explanations, mentions and retained evidence images. Images open in a fit-to-window or actual-size dialog.
- Search includes scene/event context, source text and assigned characters. Filters isolate events needing attention, events not personally reviewed and applied reanalyze changes.
- Unresolved rows, failed events, low description confidence and speaker/anchor disagreements are marked for attention. A disagreement is a review flag, not a declaration that the anchor is correct.
- Personal review marks are stored in browser-local storage under a snapshot-specific key. They do not edit semantic decisions, clear pipeline failures or change any frozen artifact.
- The workspace supports desktop and narrow screens, keyboard navigation, reduced-motion preferences and direct offline `file://` opening. It loads no remote fonts, libraries or assets.

## Build a portable review website

```powershell
venv/Scripts/python.exe -B scripts/preview_story_review.py --run-dir "<saved-run-directory>" --output "<review-output-folder>" --source-folder "D:/download/EN-data/Iris Zero/EN/Chapter 1"
```

Open `index.html` in the output folder. Available stage pages link to one another. Original source images produce the graph preview; analyze/reanalyze copy retained event evidence after verifying its checksum. Omitting `--source-folder` leaves graph images unavailable when that graph has no saved event packets.

The builder verifies source artifact hashes, records a `preview-report.json`, and makes no model requests. It writes a separate presentation folder and does not modify frozen result files or manifests. Automatic stage reviews continue to be generated by `write_review`; the existing rebuild script also uses this interface.

For r9, the generated workspace is `outputs/storylens-r9-preview/index.html`. Source snapshots retain their original text and language; the new interface labels are English.

## Validation

Model-free renderer/pipeline coverage:

```powershell
$env:PYTHONPATH = 'src'
venv/Scripts/python.exe -B -m unittest discover -s tests -p 'test_*story_graph*.py' -v
```

Optional browser checks use an existing Playwright Core installation and browser executable:

```powershell
node scripts/check_story_review_ui.mjs --review-dir "<review-output-folder>" --playwright-module "<playwright-core>/index.mjs" --browser "<browser-executable>"
```

Browser reports and desktop/mobile screenshots are written under `qa/`. The r9 workspace passed 26 model-free tests and 21 browser checks, including source immutability, retained-image integrity, tree interaction, filtering, image zoom, mobile overflow, keyboard traversal and review-progress persistence.
